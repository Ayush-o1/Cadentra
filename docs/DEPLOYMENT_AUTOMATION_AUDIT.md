# Deployment automation audit

Written 2026-11-16. It records what could be automated for hosting Cadentra at **₹0**, what was actually done, and what is still unverified.

Labels used throughout, and only when true:

- **VERIFIED LOCALLY**: executed on this computer and the result observed.
- **VERIFIED VIA API**: a provider API answered successfully and the result was checked.
- **VERIFIED LIVE**: tested on the deployed application. _Nothing is in this category yet: nothing is deployed._
- **DOCUMENTATION CONFIRMED**: current official documentation says so; not tested on your account.
- **REQUIRES MY ACTION**: needs your account, approval or a secret.
- **NOT VERIFIED**: could not be tested.

## Summary

1. **Keep the architecture: Render (free web service) + TiDB (free) + Resend (free) + GitHub Actions.** The alternatives are worse for a strict ₹0 budget (details below).
2. **A real TiDB database already exists for verification**, created without an account through TiDB Cloud's official "Zero" API. I connected to it once over verified TLS and read its version (TiDB v8.5.3). **I was then blocked from running the compatibility suite on it** because it is an external service you had not approved by name. Approving it is the single decision that unblocks live database verification.
3. **Deployment is scripted, not performed.** Render service creation, Resend webhook creation, GitHub secrets and a full live check are scripts under `scripts/deploy/`. They are tested as far as possible without your credentials (see the table). Nothing is deployed and no Render service was created.
4. **One design change protects your other projects:** the "wake and tick" workflow now runs hourly, not every 5 minutes. Render's 750 free instance hours a month are shared by every free service in the workspace (you have six running). A service pinged every 5 minutes never sleeps, uses about 744 hours alone, and would get **all** of them suspended.

### A mistake to disclose

While inspecting the Render CLI's configuration file, a redaction command of mine failed and printed the CLI's stored API key and refresh token into this session's output. They are your credentials for your Render account. **Rotate them**: Render dashboard → Account Settings → API Keys (<https://dashboard.render.com/u/settings>) → revoke any key you do not recognise, then run `render login` again. I did not use them directly and will not read that file again.

## Architecture decision

| Option                                                      | Verdict                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Render + TiDB Starter + Resend (current)**             | **Recommended.** All three have a no-card free tier. TiDB is MySQL-compatible with a documented workaround for the one blocker (`SKIP LOCKED`). Cost: ₹0. Caveats: Render sleeps after 15 idle minutes; TiDB's free allowance is 50 million request units a month, after which it refuses new connections; Resend's free plan is 100 emails a day, 3,000 a month, one webhook endpoint |
| B. Render + another free managed MySQL                      | **Does not exist any more.** Aiven's official documentation says free MySQL services can no longer be created (since 2026-11-06) and existing ones are deleted on 2026-12-21 (<https://aiven.io/docs/products/mysql/concepts/mysql-free-tier>)                                                                                                                                         |
| C. Render Postgres (free)                                   | **Rejected.** Free databases expire after 30 days, only one per workspace, 1 GB. Moving to Postgres means rewriting the Prisma schema, the hand-written constraints and every raw query for a worse deployment story                                                                                                                                                                   |
| D. Another host (Koyeb, Fly.io, Railway, Cloud Run, Oracle) | **Not chosen.** Koyeb's free instance sleeps after an hour and its card requirement could not be confirmed. For the others I did not verify current free terms; they are generally trial- or card-based, which is the risk you ruled out, and Render already works for you. This is a judgement, not a tested comparison                                                               |

## Risks that remain

- **Free-hours sharing on Render** (above). Check **Billing → Monthly Included Usage** (<https://dashboard.render.com/billing#included-usage>) after a week. If the shared total approaches 750, disable the "Wake and tick" workflow (Actions tab → Disable workflow); the app then only sends while someone is using it.
- **TiDB request units.** At the 10-second poll interval the worker is estimated to use a few million of the 50 million monthly units. That estimate was not measured. The TiDB console shows real usage.
- **Resend without a domain** can only reach your own address and test addresses. The live check uses test addresses only.
- **CHECK constraints** may be inactive on TiDB (not yet observed).
- The worker only runs while the service is awake.
